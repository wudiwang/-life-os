# 饮食记录与健康数据方案（规划，未实施）

> 2026-10-14 记录。配合「一周食谱」（生酮）模块使用。用户确认要做后再动手。

## 一、饮食核算：拍一次照，以后报名字就行

### 需求原话要点
- 每天吃的东西拍照发过来，核算热量、蛋白质，判断是否符合生酮要求。
- 不是每次都拍：第一次拍「711 黑咖啡」「711 鸡胸肉（80 大卡）」，之后只说「711 黑咖啡」就能认出来并核算。
- 常吃的预计只有 7–8 种：坚果、牛油果、空气炸锅鸡腿、烤鱼等。

### 设计：个人食物库 + 两条录入路
```
第一次：TG 发照片（可带一句「711 鸡胸肉」）
  → 本机 bot 下载图片 → ai_jobs(kind=food_recognize) → 本机大模型读包装营养成分表/估份量
  → 回一张确认卡：名称、份量、热量、蛋白、脂肪、净碳 → 用户回「对」入库
  → 写 food_items（个人食物库，带别名 + 照片）+ 写当天 food_logs

以后：TG 发「711 黑咖啡」「鸡腿 2 个 牛油果半个」
  → 先在 food_items 按名称/别名做确定性匹配（不调大模型，秒回）
  → 匹配不上才交给本机大模型，并提示「要不要拍张照建档」
```
- 有营养成分表的包装食品（711 系列）以包装数字为准，最准；自制菜（空气炸锅鸡腿）按生重 + 做法估算，建档时让用户确认一次，之后固定沿用。
- 份量用倍数：「鸡胸肉 2」= 2 份；「牛油果半个」= 0.5。

### 表结构草案（v11_food.sql）
- `food_items`：id, name, aliases(text[]), unit_label（如「1 盒 / 1 个」）, kcal, protein_g, fat_g, net_carb_g, photo_url, source（label=包装成分表 / estimate=估算）, note
- `food_logs`：id, log_date, eaten_at, food_item_id（可空）, raw_text, qty, kcal, protein_g, fat_g, net_carb_g（入库时按份量算好的快照，食物库日后改数不影响历史）

### 每日核算口径（对照一周食谱的目标）
- 净碳 ≤ 30g、蛋白质 1.2–1.6 g/kg（需体重，取健康模块最新 weight）、热量只作参考。
- 晚 21:30 收工简报里加一行：今日热量 / 蛋白 / 净碳 + 是否达标 + 差什么（如「蛋白还差 25g，加一盒鸡胸肉」）。
- 网页：「一周食谱」页加「今日饮食」卡片与 7 日趋势，食物库可增删改。

## 二、Apple Watch 数据接入（买表后）

### 现实约束
苹果健康（HealthKit）数据只在 iPhone 本机，没有云端 API，网页无法直接拉取。可行路径：
1. **Health Auto Export 类 App（推荐）**：定时把健康数据以 JSON POST 到指定地址 → 新增 `api/health-ingest.js`（Vercel，带口令校验）→ 写 `health_metrics`。全自动，最省心。
2. **iOS 快捷指令**：每天定时读取步数/睡眠/静息心率等，POST 到同一个接口。免费，但字段要逐个配。
3. **手动导出**：健康 App 导出 export.zip → 本机脚本解析导入。只适合补历史数据。

### 值得接的指标与分析
- 睡眠时长/阶段、静息心率、HRV、步数、活动消耗、体能训练。
- 有价值的交叉分析（周报推 TG）：
  - 喝酒/熬夜当晚 → 次日 HRV、静息心率变化，量化「放纵」代价。
  - 净碳与体重/体脂的周趋势；蛋白达标天数 vs 肌肉量（InBody）。
  - 生酮第 1–2 周适应期的静息心率、睡眠变化。

## 三、实施顺序建议
1. 食物库 + TG 文字记录 + 晚报核算（不依赖照片，最快见效）
2. TG 照片建档（bot 加图片处理 + ai_jobs 新 kind）
3. 网页「今日饮食」卡与趋势
4. 买表后接 Apple Watch 数据，再做交叉分析与周报推送
