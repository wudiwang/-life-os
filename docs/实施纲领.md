# 「人生 OS」个人管理系统 —— 项目实施纲领

> 版本 v1.0 ｜ 2026-07-07 ｜ 本文件是项目的总指导文件，所有开发按此推进。

---

## 一、项目愿景

把"我这个人"——身体、习惯、目标、工作、情感、认知、生活体验——从一堆无序的感觉感受，**数字化、量化地记录下来**，让自己：

1. **看清自己**：我是什么样的人，处在什么阶段，状态如何；
2. **指导当下**：当下怎么做才能更好地生活，数据说话，不迷蒙；
3. **不留遗憾**：热爱生活，记录美好，朝目标前进，把这一生过明白。

一句话：**每天记录我的生活、感悟、目标、健康，成为真正了解我的数字分身底座。**

---

## 二、总体架构（沿用「领航」项目已验证的架构）

参考 `lh-pm-workbench`，完全复用同一套技术选型与发布流程：

| 层 | 选型 | 说明 |
|---|---|---|
| 前端 | React 19 + Vite | 纯 inline 样式（无 Tailwind），zustand 管全局态 |
| 路由 | App.jsx switch 页面切换 | Sidebar + MainLayout，与领航一致 |
| 数据库 | Supabase (Postgres) | 建表 SQL 放 `supabase/*.sql`，在 Supabase SQL Editor 手动执行 |
| 文件存储 | Supabase Storage | 体检报告等附件，bucket: `attachments` |
| 服务端 | Vercel Serverless (`api/*.js`) | AI 分析等需要密钥的调用走服务端 |
| AI | Claude API | `api/ai-review.js`，密钥放 Vercel 环境变量 |
| 部署 | git push → Vercel 自动构建 | 与领航完全相同的发布链路 |

**关键设计：双模式数据层（`src/lib/dataStore.js`）**

- 配置了 `VITE_SUPABASE_URL` → 走 Supabase（正式模式）；
- 未配置 → 自动降级 localStorage（**演示模式**），全部功能可本地体验；
- 所有页面通过统一的 `db.list / db.insert / db.update / db.remove` 访问数据，切换零成本。

这样即使还没拿到密钥，整个系统也能先跑起来验收；填上密钥即切换为云端永久保存。

**鉴权**：个人单用户系统，沿用领航约定——前端 anon key + 表关闭 RLS + 可选访问口令（Settings 中设置，localStorage 记忆）。后续如需多设备强安全，再升级 Supabase Auth。

## 三、模块蓝图（10 个模块）

### 1. 🏠 人生看板（Dashboard）
- 总览：今日待办、习惯打卡进度、进行中目标、最近健康指标、本周记录数；
- **人生阶段面板**：年龄/阶段定位，该阶段的重点事项建议（AI 生成 + 手动维护）；
- 各模块数据汇聚成"人生仪表盘"，一屏看清当下状态。

### 2. ❤️ 健康（Health）
- **指标记录**：身高、体重、血压（收缩/舒张）、心率、血糖、血脂等，支持自定义指标；时间序列存储，趋势图展示；
- **体检报告**：上传检测机构报告（PDF/图片 → Supabase Storage），永久保存，附摘要与 AI 解读；
- **AI 评价**：基于指标历史给出评价与建议；
- 异常提醒（如体重连续上涨、血压偏高）。

### 3. 🔁 习惯（Habits）
- 习惯定义（健身、阅读、早睡……）+ 每日打卡；
- 连续天数（streak）、周/月完成率统计；
- AI 依据打卡数据给出评价与调整建议。

### 4. 🎯 目标（Goals）
- 分层目标：年 → 季 → 月 → 短期，支持父子关联；
- **里程碑/检查点**：每个目标可设多个检查点（截止日 + 验收标准），到点录入结果做自我检验（达成/部分/未达成 + 复盘）;
- **过程记录**：目标下的每日推进日志，形成实施-管控闭环；
- 状态流转：规划中 → 进行中 → 已完成 / 已放弃。

### 5. 💼 工作（Work）
- **每日待办**：优先级、截止时间、完成状态；
- **工作日志**：每日记录（做了什么/产出/问题），支撑汇报；
- **职责档案**：我的职责范围、产出要求、注意事项；
- **人际地图**：汇报人/上级/下级/同事档案——职责、性格、相处姿态、注意点，可做关系分析。

### 6. 🧭 探索世界（Explore）
- 美食/餐厅、旅行、经历、新体验的记录：时间、地点、评分、感受、照片；
- 对真实世界认知提升的记录，"生活的美好"清单。

### 7. 🧠 第二大脑（Knowledge）
- 外挂大脑：专业知识、生活感悟、信息收藏，Markdown 笔记 + 分类 + 标签；
- 记录"我都积累了哪些东西"，可检索。

### 8. 💞 情感关系（Relations）
- 亲情/友情/爱情分类的重要之人档案（生日、亲密度、备注）；
- 互动记录：见面、通话、值得记住的瞬间与感受；
- 提醒：生日、太久未联系。

### 9. 📔 每日一记（Journal）
- 最低成本的每天记录入口：心情评分 + 今日文字 + 感恩/美好瞬间；
- 是全系统的"日频心跳"，供 AI 分析情绪与状态趋势。

### 10. 🤖 AI 分析（AI）
- 任一模块数据 → 生成评价/建议（走 `api/ai-review.js`，Claude API）；
- 综合分析：结合多模块数据回答"我现在处于什么状态、该注意什么"；
- 分析历史留存。

### ⚙️ 设置（Settings）
- 密钥/连接状态、访问口令、数据导出（JSON 备份）、演示数据一键清空。

### 后续扩展方向（本期不做，列入路线图）
财务管理（收支/资产）、睡眠与饮食记录、阅读清单、时间/精力管理、年度复盘生成器、遗愿清单（Bucket List）、物品/订阅管理、微信/手机端 PWA。

**学习系统（用户已确认方向，待启动）**："步步留痕"式终身学习——一个知识点一个笔记，AI 负责记忆检测、间隔重复复习（SRS）、出题考试验证掌握度。目标场景：泰语入门、雅思 7.5、专业能力提升。技术路径：knowledge_notes 加复习字段（next_review_at/proficiency）→ 大仙每日推送复习卡片+抽查提问 → 定期模拟考试评分。依据：检索练习+间隔重复是认知科学中效果最强的学习法，方向成立。

**第二大脑演进（Karpathy LLM Wiki 思路）**：已落地 Ingest（大仙自动归档）、Query 回写、互链、矛盾标注、总纲索引；待做：定期 Lint（矛盾/过时/孤儿笔记体检，可做成每周任务）、TG 文件直接入库、笔记量过几百篇后启用 pgvector 语义检索（Supabase 原生支持，同库加列即可）。

## 四、数据模型（supabase/v1_init.sql）

| 表 | 用途 | 关键字段 |
|---|---|---|
| health_metrics | 健康指标时序 | metric_type, value_num, value2_num(舒张压), unit, measured_at, note |
| health_reports | 体检报告 | title, org, report_date, file_url, summary, ai_review |
| habits | 习惯定义 | name, icon, target_per_week, remind_time, active |
| habit_logs | 打卡记录 | habit_id, log_date, done, note |
| goals | 目标 | title, level(year/quarter/month/short), parent_id, start_date, due_date, status, review_note |
| goal_milestones | 里程碑/检查点 | goal_id, title, due_date, check_criteria, status, check_result, checked_at |
| goal_logs | 目标过程记录 | goal_id, log_date, content |
| work_todos | 工作待办 | title, priority, due_date, status |
| work_logs | 工作日志 | log_date, content, output, issues |
| work_profile | 职责档案 | field(duty/output/care), content |
| work_contacts | 工作人际 | name, dept, role, relation, duties, stance, notes |
| explore_records | 探索记录 | title, category, record_date, location, rating, content |
| knowledge_notes | 第二大脑 | title, category, tags, content, source |
| relation_people | 情感之人 | name, rel_type, birthday, closeness, notes |
| relation_logs | 互动记录 | person_id, log_date, event, feeling |
| journal_entries | 每日一记 | entry_date, mood(1-5), content, gratitude |
| ai_reviews | AI 分析历史 | module, prompt_summary, content |
| life_stage | 人生阶段面板 | field(stage/focus/advice), content |

所有表：`id uuid default gen_random_uuid()`、`created_at timestamptz default now()`、**disable row level security**（与领航一致）。时间展示统一北京时间（UTC+8）。

## 五、里程碑计划与检查点（loop 执行方式）

每个里程碑完成后必须通过检查点（`npm run build` + eslint 0 error + 功能自检）才进入下一个：

| 里程碑 | 内容 | 检查点 |

| M0 | 纲领文档 + 项目骨架 + git init | install/build 通过 |

| M2 | 健康 / 习惯 / 目标 三大核心模块 | build 通过 + 演示模式可用 |
| M3 | 工作 / 探索 / 第二大脑 / 情感 / 日记 | build 通过 |
| M4 | 人生看板 + AI 分析 + 设置 | build 通过 |
| M5 | README / 部署指南 / CLAUDE.md + 最终验证 + git 提交 | 全绿交付 |

## 六、交付后你要做的事（晨间清单）

1. Supabase 新建项目 → SQL Editor 跑 `supabase/v1_init.sql` → Storage 建 `attachments` bucket（public）；
2. 复制 `.env.example` 为 `.env`，填 `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY`；
3. GitHub 建仓库 → push → Vercel 导入（环境变量加上述 2 个 + `CLAUDE_API_KEY`）；
4. 打开站点验收。详细步骤见《部署指南.md》。
